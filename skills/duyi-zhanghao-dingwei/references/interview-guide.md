# 提问配额、最低可用线与默认值

每阶段按下列核心问题推进，覆盖配额后交付阶段结果。用户前文明确回答过的项不重复询问，答不出或跳过的项保留状态。

## 三条硬规则

1. **配额制**：每阶段核心问题不超过配额数。用完就出结果，不追加。
2. **补充澄清不挤掉核心项**：先完成每个核心项，同一话题最多澄清一次。不能拿追问替代尚未覆盖的问题；用户答不出就标记并继续。
3. **跳过即填默认**：用户答不出时，从默认值表取一个填上，标注来源，继续往下。

## 开始前先选模式

模式选择不计入四个阶段的配额：

- 从零定位：只使用本轮提供的信息，不读取工作区旧定位资料。没有文件或目录也能开始。
- 继续已有定位：使用用户贴出的资料，或读取用户明确指定的文件；没有提供时先请用户提供。

未选择时默认从零定位，简短说明后开始第一题。交付方式另行判断，默认在聊天里交付；只有用户要求保存时才确定文件位置。

## 阶段收尾清单（出结果之前必做）

产出阶段结果前，逐条核对本阶段的配额问题。每个问题只能落在三种状态之一：

| 状态 | 含义 | 怎么标 |
| --- | --- | --- |
| 已有用户答案 | 本题已问并回答，或前文已经明确回答 | 按用户事实或用户偏好记录，不重复问 |
| 已问到，用户没答 | 用户说跳过、记不清、不知道 | 用默认值，标"默认值（用户跳过）" |
| 没问到 | AI 漏问 | **不允许出现**。回到访谈把问题问出来 |

**未回答且未询问的项不算前两种，也不准用默认值补上。** 核心项还未覆盖时，可以更新草案，但不能宣布阶段完成。

清点用于内部核对。阶段结果保留相关待确认项和来源，不附执行统计。

## 用户跳过时说什么

用户说"不知道""想不起来""跳过""你看着办"时，用类似下面的话接住，然后立刻往下走：

> 没关系，我先按「某某」填上，标成待确认，你后面看到不对再改。

不要说的：

> 你再想想，这个对定位挺重要的。

不要用"这个很重要"来挽留。v0.1 阶段没有哪个字段重要到必须当场问出来。

## 默认值表

只有问过后用户给不出时才使用下表，并在结果中标注“默认值（用户跳过），待确认”。不替未问项填值。

| 缺什么 | 默认值 |
| --- | --- |
| 说不清赛道 | 事实簇里证据最强的那一簇 |
| 说不出读者是谁 | 和用户当初遇到这个问题时处境相同的人 |
| 说不清读者的认知状态 | 刚接触，还在找入门路径 |
| 说不清表达方式 | 用大白话讲清楚，配具体例子 |
| 说不出核心价值 | 少走弯路 |
| 说不出内容形式 | 解释 + 问答；有真实来源时再加入案例 |
| 说不清平台 | 小红书 |
| 说不清每周投入时间 | 待确认，不替用户估算 |
| 说不清公开边界 | 待确认，默认不扩大公开范围 |
| 不愿真人出镜 | 不用真人，用文字、截图或示意图 |
| 想不出昵称 | 给三个候选让他挑 |
| 没有可公开的成果 | 使用用户已确认的当前行动；没有当前行动则写待确认 |
| 说不清业务目标 | 尚未确定 |

## 阶段一：个人定位

配额 4 个问题。**4 个都要问到**，问完就停，不再追加。

1. 你现在主要在做什么？处于什么阶段？
2. 别人最常因为什么具体问题来问你？
3. 有没有一件你做成、帮到别人或者踩过坑的事？
4. 这些经历里，哪些能公开，哪些要匿名，哪些不能提？

别人来问的问题只记录为需求线索，不据此判定本人能够解决；具体能力和行动来自明确自述，缺少时留待确认。

最低可用线：**知道用户现在在做什么，并且至少知道一件他做过的事或正在发生的行动。**

第 1 题答完就可以先给一版草案让用户改，不用憋到最后。空缺部分写待确认；基于现有信息推导的建议标明来源。**给草案早不等于少问问题**，剩下 3 个照问。

产出：个人定位草案 + 2 到 3 个候选赛道（推导方法见 [niche-guide.md](niche-guide.md)）。

交付后问一句："你看哪里不对，直接改。"

## 阶段二：账号定位

配额 4 个问题。**4 个都要问到**，问完就停。本阶段多数内容可以从阶段一和赛道推导出来，但这四个问题不是"可问可不问"，是必问。

1. 在这个领域里，你最愿意长期讲哪一类问题？
2. 关注你的人，大概处在什么状态？（完全不了解 / 懂一点做不好 / 在做但卡住）
3. 你希望看完你内容的人，带走什么？
4. 这个账号现阶段最想带来什么？（例如积累表达、获得咨询、验证产品；不确定也可以直接跳过）

最低可用线：**知道讲哪个领域、讲给谁、用户凭什么讲。**

交付：一句话账号定位 + 结构化账号定位。

交付后问一句："这句话你愿意长期用吗？哪里别扭直接说。"

## 阶段三：内容定位

配额 2 个问题。**2 个都要问到**，问完就停。这是推导为主的一阶段，用户只需挑和改。

1. 这三类内容里，哪些你现在就能讲，哪些得先做出来才能讲？
2. 每周大概能投入多少时间？

最低可用线：**赛道和读者明确即可产出。**

交付：核心主题 + 2 到 3 个支柱 + 3 到 5 种内容形式 + 前 5 条方向。

交付后问一句："哪几个方向你现在就能写？划掉你不想做的。"

## 阶段四：账号包装

配额 3 个问题。**3 个都要问到**，问完就停。第一个问题必须先问平台并等待回答；平台明确后再问其余两项，最后生成方案。

1. 主要发在哪个平台？前文已经明确回答时沿用该答案；未回答时先单独问并等待，明确跳过才用默认平台。
2. 愿意真人出镜或用本人头像吗？
3. 有没有你明确不想用的词、身份或风格？

最低可用线：**赛道、读者、核心价值、平台明确即可产出。**

昵称、简介、头像方向、主页其他字段都要给具体内容，不要给"可以从某某角度考虑"这类方向性描述。具体平台字段尚未核验时标待核，不把常见字段示例当成已经确认可用。

交付 2 到 3 套方案后问一句："选一套，或者告诉我哪套的哪一行要改。"

最终方案选定后，完整展示定位总览和账号包装，邀请用户确认当前版本或指出修改处。默认聊天交付；用户要求保存时，再按已确认的文件范围写入。

## 两种完成状态

- **访谈已完成**：四阶段问题都已问到，用户跳过的内容已明确标为默认值或待确认，四阶段草案都已交付。
- **定位已最终确认**：用户在看到两份完整结果后，明确确认当前版本；如果仍有待确认项，用户也必须明确接受这些项目暂时保留为待确认。

有待确认项但没有最后的明确确认时，只能报告“访谈已完成，定位尚未最终确认”。不要替用户勾选两份文件中的“本人确认”。

## 信息怎么标记

每条信息都带上来源，写进文件时保持：

- 用户事实：用户说过并确认
- 用户偏好：用户表明的方向
- AI 建议：基于事实推导的方案
- 默认值（用户跳过）：用户**被问到但没给**，按上表填的。标来源时必须写"用户跳过"，不能只写"默认值"，否则事后分不清是用户没答还是 AI 没问

只有前两类进正式字段。
