# 保存、局部更新与重命名

## 默认交付

没有明确保存要求时，在聊天里交付，不写文件、不改名、不更新资料库导航。

## 保存整理稿

1. 使用用户指定的目标目录和文件名，并读取该位置现有规则；没有提供位置时先询问，聊天交付可先完成。
2. 优先将整理稿另存为用户指定的新文件，原始材料保持不变。若目标已经存在，展示差异和拟更新范围，不静默覆盖重要正文。
3. 用户要求原位整理原始日记时，先保留用户指定位置的可恢复原始副本或已存在的不可变原件，展示完整待写稿，取得明确写入授权后再保存。不能仅因“帮我整理”而覆盖源文件。
4. 原文附录按实际输入完整保存。保留原始字节和换行形式，原文含代码块时使用更长围栏，不改标题层级以求美观。
5. 写后重新读取实际结果，核对整理正文和附录原文，检查原稿或副本仍完整。文件指纹只证明字节相符，不证明日记事实独立核验。

## 已整理日记的局部修订

- 只修改用户指出的相关段落，保留无关内容、手工备注、附件与链接。
- 已有原文附录不可重写、删改或换成 AI 摘要。需要追加新原话时保留之前原文，再追加本次新输入及其来源范围，不重新拼造录音原稿。
- 日期疑点、原文矛盾或归属待核只在必要位置说明，不替用户裁决。
- 旧格式缺少判断、待办或行动节时，只补原文确有的内容；原文没有则不增加。

## 日期与主题命名

可以建议“日期，主题”的文件名，日期来自已确认输入，主题来自当日真实主线。建议名字不等于授权重命名。

用户明确要求重命名时：

1. 展示旧名、新名和受影响的链接范围。目标同名文件已存在时停止该项，不合并、不覆盖。
2. 在用户指定的资料库范围内检查指向旧名的链接；不能确认引用范围时先说明，不宣称全部链接安全。
3. 遵循目标位置的移动与结构修改规则，按已获授权范围执行。不要擅自批量搬文件、重组目录或同步其他库。
4. 更新实际指向旧名的导航、普通链接和双链，保留其他正文。普通 Markdown 链接的中文路径用可靠 URL 编码工具生成，避免手写编码。
5. 重新读取日记、导航和引用文件，确认链接指向实际目标且原文仍完整。未知或历史缺失单独说明，不把链接改指相似材料。

只报告实际保存、更新或改名的结果。权限不足时保留聊天交付和具体待写差异，不创建空文件假装完成。
