# 个人使用说明指南

帮助陌生读者看懂“你是谁、这份礼物能帮我什么、怎样取得和用起来、为什么值得继续了解”。默认做一份个人说明书与资料指南的合篇，把有用的资源放在前面，再展开相关经历、做法、案例、适合人群和连接方式。

使用当前被介绍者的材料，不继承示例作者的职业、课程、资源数量、工具、成绩或商业模式。没有付费产品也能成稿；用户只要个人介绍时不强加见面礼。用户指定结构时先读其现行版本，沿用章节的作用与顺序，内容按本人事实填入。

## 输入与启动

| 输入 | 最少需要什么 | 如何取得 |
|---|---|---|
| 读者与用途 | 给谁看，在哪个场景使用 | 从请求提取；不清楚时一次问一个关键问题 |
| 本人材料 | 一个资料入口或一段口述，说明现在做什么及相关经历 | 读取指定知识库、文档、作品或本轮原话 |
| 自用资料 | 可选的模板、清单、工具、方法、教程或案例 | 读实际内容，确认本人如何用、能给谁用、是否允许分享 |
| 领取与连接 | 真实资源文件或入口；可选的联系渠道和服务边界 | 沿用本人提供的入口，不生成假链接、假二维码或支持承诺 |
| 证明素材 | 可选的作品、照片、反馈、账号或订单截图 | 有就核对和选用，没有不编造、不强制补齐 |
| 呈现形式 | 可选；默认大字单栏图文 HTML | 沿用已明确的选择；改变文档、网页、组图等主要形式前先沟通 |

启动示例：“帮我做一份给刚认识我的读者的个人说明书与资料指南，把我平时自用、能帮到他们的东西作为见面礼。资料在指定目录，希望他们能看懂我、取到资料并知道怎么用。”

先定位本轮资料范围、现行定位和已有版本，读取目标库规则与原件。已有定位直接使用，不重复完整定位访谈。需要重新选赛道或设计尚不存在的产品时，指出任务边界，按用户要求另行处理。

不要求学员先填大表或整理完全部文件。没提供资料时，直接开始一次只问一个问题的短访谈，先问“你现在主要在做什么？”收到回答再补目标读者、相关经历、自用做法和可分享范围，逐步记录成草稿，不假造回答或一次问完整套问卷。已有材料能回答的内容不重问。

没有现成分享物但有真实做法时，帮其挑选可整理成清单、模板或短指南的最小内容。新整理的东西是待审阅草稿，不能称为长期自用、已验证或已可领取；确认内容和可用入口后再写领取承诺。完全没有经历或做法时继续定向访谈，不用通用生成物冒充本人资产。咨询记录只在提供或授权范围内读取；模拟疑问保留模拟性质。

## 工作流程

### 1. 整理事实与读者问题

起稿时读取 [内容契约](references/content-contract.md)。建立内部素材依据表，记录事实、主体、来源、时效、确认状态、公开范围和可用图片。

- 当前身份、过去经历、当前服务和未来打算分开；历史报价与交付不自动变为现行承诺。
- 更新稿先读本人指定的现行版本。与旧稿、测试产物冲突时按确认状态和来源判断，不能仅凭文件修改时间选择，更不能用旧试跑稿覆盖新事实。
- 本人原话是来源；库中的第一人称、他人案例和 AI 分析不能直接当本人经历。有冲突时回查原件或定向补问。
- 对每个真实或模拟疑问，确定正文需要回答的内容，只收与本次用途有关的问题。

### 2. 盘点资源并选出见面礼

读取实际资料，按“读者的问题、本人如何使用、能提供什么、第一次怎么用、获取入口、分享权限和限制”做内部资源表。挑选能帮目标读者完成一个小动作、与本人经历相关的内容，不为了显得丰富把所有资料塞进指南。

先查已有材料，再补问影响身份、实际资源、关键事实或公开边界的一项缺口；回答后立即更新草稿，同一问题不换说法反复追问。没有资料库并不等于没有经验；有资料名或链接也不等于已读内容、已能使用或有权再分享。

关键信息仍不明确时，输出已能写出的内部草稿和具体待补项，状态为“资料待补”。缺少非必要数字、图片或案例可省略。没有产品、没有大成绩、没有截图，不构成无法成稿的理由。

没有产品时写经历、作品、正在做的事与联系入口，不生成价格、报名、课程交付或已经收费的承诺。有服务时按实际材料写帮助对象、提供内容、参与条件和边界。

### 3. 写合篇与使用指南，匹配配图

读取 [合篇结构与资源指南](references/guide-structure.md)。默认顺序是：简短认识本人 → 小礼物及取用方法 → 经验来源 → 现在帮助推进的事 → 真实案例 → 适合谁 → 怎么连接。无材料的节合并或省略，不填虚构案例或服务。

资源条目先讲读者熟悉的问题、具体用途和第一次要做的动作，再写必要名称。说明要准备什么、会得到什么、怎么知道用对，以及实际限制。资源多时按读者任务归组，把深度说明交给真实资源文件，主文避免反复介绍同一功能。

仅个人介绍模式按内容契约写本人、相关经历、当前行动、帮助内容与了解入口。默认交付一份；需要快速转发或用户明确要求时另做简介，和合篇分别可读，不默认增加两篇长文。所有版本的事实、资源可用状态和承诺保持一致。

把术语转成读者的问题、具体动作和实际提供的东西，必要术语首次简要解释。不将“提供模板或工具”写成“保证做成、成交或稳定收入”。

选图支撑相邻论断，写有阅读意义的图注。核对原图与文字、主体、日期、金额和结果阶段；保护无关的第三方识别信息，保留原件。没有可安全使用的图片时交付文字稿，说明配图缺口。

### 4. 自检与读者试读

稿件形成后读取 [读者试读](references/reader-review.md)，检查事实、核心理解、术语、重复、图文对应和承诺边界。还要用实际文件或入口核查：读者能否取得资源，能否从第一步开始，是否误以为领取就包含咨询、陪跑或保证结果。

疑问定位到句子或图片，再决定补充、替换、合并、删去或放进资源内页，不得将所有疑问逐条追加到主文。实质修改后检查受影响部分，不用旧版结论替新版通过。

复杂介绍、多类读者或仍有关键误读时，若环境支持，可安排一次独立子代理试读；只给当前文案、可见配图、读者可取得的资料和读者场景，代理只读。没有委派能力或用户不希望委派时由主代理模拟，记录实际方式。模拟不是实际用户反馈或转化率证明。

### 5. 让学员审阅完整预览

先完成具体图文稿、资源指南和可用预览，再请本人核对事实、语气、分享权限、资源取用及联系边界。已采纳的句子、资料和呈现选择沿用；局部确认不扩大为整份采纳。

等待审阅时仍可完成已授权的本地预览和检查，保存为“待本人审阅”；不覆盖当前权威原件，不把没有回复当采纳。出现新事实缺口回到补问，其余修改直接落实。

### 6. 生成选定形式并核查保存

生成预览、正式排版或保存时读取 [交付与排版](references/delivery.md)。默认生成合篇 HTML、可编辑 Markdown、配图、实际资源或真实取用入口和阅读入口。可用 `scripts/render_article.py` 渲染 HTML，它只处理格式和已选本地图片，不负责事实判断。

指定飞书时使用可用的飞书能力生成对应阅读版本，保留本地正文和配图；不强制额外生成未要求的形式。写入前沿用当前授权，不把撰写扩展成公开发布或改平台资料。

打开实际成品，检查手机宽度下的正文、截图、缩放、图片放大、隐私处理及链接。工具无法完成的视觉或远端检查记为未验证，不能以静态检查冒充实际可读性。

要求知识库归档时按库规则保存，复用已有图片原件并建立阅读入口，保留远程链接、正文和资源去向；更新已有版本时保留手工内容和历史。写后回读正文、图片、资源及链接。脚本、试跑数据与开发记录留在工作目录，不放进知识库或 Skill 正文。

## 输出与完成状态

对外文章只含可公开的介绍、图注与必要数据口径。提示词、来源路径、执行过程、修改记录和待补项放独立内部记录或聊天汇报。正文不使用破折号。

| 输出 | 用途 |
|---|---|
| 个人说明书与自用资料指南 | 一份独立可读的合篇；仅个人介绍模式按实际范围写 |
| 资源文件或真实入口 | 分享获准的实际内容，配套取用与起步说明 |
| 可编辑正文 | Markdown，供更新与知识库读取 |
| 简介版（按需） | 快速转发，指向合篇或资源入口 |
| 对应配图 | 安全展示的图片，保留原件归属 |
| 阅读入口 | 关联阅读文件、正文、资源和已创建的外部链接 |
| 内部核查记录 | 素材与资源依据、试读疑问、实际检查与未完成项 |

分别报告文案状态、本人采纳、成品核查和保存状态，四者不能相互推断：

- **资料待补**：关键信息不足，交付具体草稿与缺口，不称对外最终版。
- **待本人审阅**：完整稿已形成，尚未取得本人采纳。
- **文案已采纳，交付待完成**：本人采纳有效，但排版、远端写入或保存有未完成项。
- **交付完成**：本人确认可用，关键事实有依据，核心含义清楚，实际成品检查通过，所需文件、图片和入口保存完整；含见面礼时实际资源可取得，指南与内容相符。

汇报具体文件或链接及实质未完成项。不要以无图、粉丝少或未销售制造不必要的补料；结构校验不能代替事实、意义和实际呈现验收。
