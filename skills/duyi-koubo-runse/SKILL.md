# 杜一口播润色

只检查口播稿怎样被听懂、怎样顺着说下去，以及口播和必要画面是否同步。保留作者的观点、经历、数据和口吻，不固定句式，不机械删重复，不以字数限制替代判断，也不虚称实际试读、预测流量或完播率。

争议性、尖锐表达和强烈立场本身不构成删改理由。保留作者的观点和锋芒，不为了降低争议、让所有人认同或让措辞更温和而删除主张、改弱结论。论据或事实有缺口时，在稿外提示内容问题；用户采纳具体内容建议后再修改。精简无功能重复时，也不能顺带删掉其承载的立场或关键限定。

## 检查范围

独立读取并检查完整口播稿，不要求先运行其他 Skill。内容诊断、用户困境、简单方法、亲身体验、内容作为正价产品试用装、承诺兑现和推理是否成立，属于 `duyi-neirong-zhenduan`；发现这些内容层问题时单独列为「待交回内容诊断」，不在本 Skill 内补新事实、改原结论或替稿子建立新前提。

未安装 `duyi-neirong-zhenduan` 时，照常完成五项口播检查，将内容问题连同原文依据列为待处理；不调用不存在的 Skill，也不自行补事实或推理前提。

只依据本次明确选定的稿件和授权辅助材料作判断。同一对话中的其他稿件、示例或未选定材料，不能自动作为本稿的事实依据。

只有选题、没有正文时，全部标准标「待补正文」，不生成段落、重复、指代或节奏问题，不把材料缺失判成表达不合格。已提供部分稿件时只判断可见部分，说明未覆盖的正文范围。平台、时长和拍摄方式只在会改变具体建议时询问，不设为开始检查的必填门槛。

## 全部标准

所有标准都要检查并使用「通过／部分通过／未通过／待补／不适用」。下面各项给出检查问题、检查方法、参考和修复方法；报告呈现判断、原文和修改建议，不输出检查过程。承接问题同时引用相邻段落，其他问题引用具体原句。没有问题也要说明通过依据，不为完成报告强找问题。

| 编号 | 标准 | 判断重点 |
|---|---|---|
| 1 | 段落承接与话题收束 | 相邻话题能否接上，已有解释是否在合适位置出现 |
| 2 | 重复功能与表达效率 | 每段是否有价值，重复是否有实际作用 |
| 3 | 指代、术语与一次听懂 | 用户能否第一次听懂对象、动作与术语 |
| 4 | 语序、停顿与说话节奏 | 语序、停顿和句子负担是否适合口头表达 |
| 5 | 必要画面指向同步 | 必要画面是否支撑口播中的操作与指向 |

## 标准 1：段落承接与话题收束

**检查问题**
- 上一段结束后，用户能否理解为什么进入下一段？
- 必要解释是否在全文已有，却出场太晚？
- 前一个话题是否恰当收束？

**检查方法**：按相邻段落及同段转折定位，引用前段末句与后段首句，区分已有解释未接上、话题未收束和需要新依据的内容问题。按目标用户常识判断必要解释，不把每个省略都当断裂。

**参考**：演示：原稿已有「待办需要负责人和期限」，却直到结尾才解释，可把这句前移到展示待办表之前。若从「会议记录很长」直接跳到「因此所有会议都应取消」，缺的是支持结论的理由，需要交回内容诊断。

**修复方法**：优先调序、收束前段或补入全文已有的必要解释。不能只加「所以」「接下来」掩盖断裂；需要新事实、新前提或改原结论时，列为待交回内容诊断，继续修其他口播问题。

## 标准 2：重复功能与表达效率

**检查问题**
- 每段是否增加理解、信任或行动价值？
- 重复是强化、解释、建立信任，还是没有新增功能？

**检查方法**：检查同段及前后跨段的语义重复，不只比较相邻句或相同词。发现冗余时必须同时引用两处或多处原文，分别说明各处功能，再判断删并会失去什么。重复承担新的解释、信任、行动或结尾回扣功能时保留；不能因前面已提过就删，也不凭篇幅判冗余。

**参考**：演示：开头提到「负责人没写清」用于说明困境，结尾再次提醒负责人是在提示执行，两处有不同作用。只有同一信息承担同一功能、也不帮助强调时才考虑合并。没有精简要求时保留具体经验和支撑。

**修复方法**：明确指出保留哪处、删除哪处或把哪些句子合并，并给出可直接替换的表述；不能只写「可以精简」「结尾合并一处」。合并保留原意、口吻和必要细节，说明保留了什么功能。已要求改稿时按下述标记式格式在原位置落实，不把全文压成摘要。

**修改示意**：前段已问「开完会，你是不是还不知道谁来做？」；后段又说「有些人开完会会出现这个问题，不知道谁来做，其实可以这样处理」。若两处只重复同一顾虑，可将后段改为「有些人会遇到这个问题，可以这样处理」，保留人群和转折。具体方法是否成立，另归内容诊断。

## 标准 3：指代、术语与一次听懂

**检查问题**
- 「它、这个、前面、后面」指向是否明确？
- 术语、转写词和对象是否让用户第一次听就知道谁做什么、得到什么？

**检查方法**：逐句核对对象、动作、结果和指代，结合全文回指；对未解释术语或疑似转写错误原样标出，不凭猜测替换。

**参考**：演示：「前面的表／后面的表」可能增加回忆负担，可按原稿已有对象点名为会议记录和待办清单。疑似转写词原样标记，先核对，不凭猜测改成新术语。

**修复方法**：前移或补出原稿已有的对象，首次出现时用通俗短语解释已知术语，拆开多重指代；无法确认的词列为待核对，不编造含义。

## 标准 4：语序、停顿与说话节奏

**检查问题**
- 语序是否符合口头表达？
- 停顿位置是否让听众先听懂主干，再接条件、例子和结论？
- 是否有难念的连续音或书面套句？

**检查方法**：按自然说话语段朗读式审看，标出主语、动作、结果和修饰关系；只判断文本可见的节奏障碍，不声称真人试读结果。

**参考**：保留用户口吻和自然重复，不以固定字数、统一开头或结尾替代判断。演示：「你把负责人、动作以及截止时间都确认之后，再发出去」可按原意调整停顿，帮助听众先抓住动作。

**修复方法**：调整已有成分顺序、补必要停顿标点、拆分多层意思，给出可直接替换的局部句子。不得为顺口添加新经历、数据或结论。

## 标准 5：必要画面指向同步

**检查问题**
- 口播说到操作、对象、位置或「看这里」时，画面是否有对应指向？
- 缺画面会不会让听众无法理解？

**检查方法**：结合提供的脚本、画面说明或成片信息，逐处对照口播指向与画面对象。有必须依赖画面的操作或指向、却没有对应材料时标待补。没有这类视觉依赖时标不适用，即使未来会拍成视频，也不因尚未给画面就判待补。

**参考**：「点击这里」「看这一列」等指向需要相应按钮、文字或动作。仅提到文档、视频或文章，不表示已经看到实际画面。

**修复方法**：补必要的截图、演示、字幕或明确指向，或把口播改成不依赖缺失画面的已有表达。拍摄方式会改变修复方案时列出待补信息。

## 交付格式

只要求诊断时使用下面的报告，给具体局部建议。已经要求润色或改稿时，先交下方完整五项检查表，再交完整原位标记稿和改动清单；不能只交标记稿而省略检查表，也不追加「是否改稿」的重复确认。

```markdown
# 口播润色检查：{稿件标题}

## 总体判断
{最影响一次听懂或顺畅推进的一点，以及它是否属于口播层问题。}

## 全部标准
| 编号 | 标准 | 判断 | 原文依据或具体缺口 | 修改建议 |
|---|---|---|---|---|
| 1 | 段落承接与话题收束 | {判断} | {引用相邻原文} | {建议／无需修改} |
| 2 | 重复功能与表达效率 | {判断} | {具体原文} | {建议／无需修改} |
| 3 | 指代、术语与一次听懂 | {判断} | {具体原文} | {建议／无需修改} |
| 4 | 语序、停顿与说话节奏 | {判断} | {具体原文} | {建议／无需修改} |
| 5 | 必要画面指向同步 | {判断} | {具体原文或待补材料} | {建议／无需修改} |

## 局部修改建议
### {必须改／建议改／可选优化}：{位置与问题}
原文：{引用；承接问题同时引用相邻段落}
问题：{具体障碍}
建议：{最小修改或需补材料}

## 待交回内容诊断
{仅列需要新事实、新前提、改原结论，或涉及用户困境、承诺兑现、推理成立与否的问题。没有则写「无」。}
```

全部标准都要呈现，同一处问题合并建议，细节优先展开最重要的 1 至 3 处。会造成误解的承接或指代问题属于「必须改」；无功能重复或明显难说清属于「建议改」；不影响理解的用词与节奏属于「可选优化」。不为小幅字词变化编造「原句喘不上气」等没有文本依据的理由。

## 标记式改稿格式

默认交付完整的原位标记稿，让用户能逐处看到原文、改后表达和删除位置。不要用整篇干净重写代替，也不要只交几个局部建议后称为已改稿。

| 类型 | 原位置的呈现方式 |
|---|---|
| 替换 | `~~原文~~ **【改后】** 新表达`，删改成对出现 |
| 纯新增 | `**【新增】** 新表达`，只能展开或衔接全文已有信息 |
| 删除 | `~~原文~~`，保留被删文字，原因放末尾改动清单 |
| 跨段合并 | 各原位置保留被合并文字的删除线，在保留位置紧接 `**【合并改后】** 合并表达`；清单注明来自哪几段、为什么放这里 |
| 还原 | `**【还原】** 恢复的原文`，清单说明撤回哪项修改 |

未改句子和段落照原文保留，不能悄悄省略、换词或改事实。既可标记局部词句，也可标记整个语段；范围应让前后文仍可辨认。标记范围覆盖所有实际变动，包括标点和连接词；不能只划去部分旧词，再改动旁边未标记的文字。段号和改动原因放报告、清单里，不插进台词。

多轮修改保留每轮原稿与标记稿，撤回的修改标明还原，不覆盖唯一原件。用户已采纳的表达可成为下一轮基准，不把未采纳的建议当成已确认内容。

### 口播修改的语义边界

- 每处替换都核对人物、事实、数字、对象范围、条件、因果和结论强弱。只调整说法，不默认把这些内容改掉。将「很多人」改成「有些人」也改变了对象范围，不能当作顺口调整直接落实。
- 例如「材料齐全的人，可以完成预约」可以调整停顿；改成「愿意多投入的人，才可能完成预约」同时改变了条件和结论强弱，属于内容建议，不得混进口播改稿。
- 内容诊断提出的建议不自动等于用户已采纳。改变观点或新增事实的方案，先留在内容诊断建议里；已有明确授权或采纳记录时再落实。
- 缺少事实、新前提或观点尚未明确的句子，在标记稿中按原样保留，不加删除线或改后标记；把问题和建议集中列为「待补事实与内容问题」，继续修改其他口播问题。只有用户已明确采纳或授权具体内容修改时，才在标记稿落实那项改动。不虚构前提或用「所以」掩盖缺口。

### 改稿交付模板

```markdown
# 标记式口播改稿：{稿件标题}

## 标记稿
{完整原稿，未改部分保持原样；各处修改都在原位置成对标记}

~~{被替换的原句}~~ **【改后】** {新表达}

**【新增】** {衔接原稿已有信息的句子}

~~{删除的重复句，仍保留可见}~~

## 改动清单
| 位置 | 类型 | 原文定位 | 改了什么、保留了什么及理由 | 优先级 |
|---|---|---|---|---|
| {位置} | {替换／新增／删除／合并／还原} | {原文片段} | {具体变化及其作用} | {必须改／建议改／可选优化} |

## 待补事实与内容问题
{需要新事实、改观点或补论据的内容及具体缺口；没有则写「无」}

{一句话说明必须处理的地方与可选修改；仍有关键缺口时明确稿件待补。}
```

模板中的删改形式是示意，只输出实际发生的类型，不为了凑齐标记制造修改。每一处实质修改都进入清单，不漏记，不用流程日志代替理由。原因是修改结果的说明，不写读文件、扫描、执行步骤等工作过程。

### 发布净稿

标记稿用于审阅，净稿用于录制或发布。用户明确要求净稿或可直接口播版时，根据已采纳的修改另交净稿；只要净稿时按用户要求交付，仍保留原件与可核对的修改记录。

净稿正文只保留面向观众的语言，不放删除线、文字标记、案例占位、工作过程、规则自述或改动说明，正文不使用破折号。关键事实或内容问题尚未解决时，不称为「可直接口播」。
