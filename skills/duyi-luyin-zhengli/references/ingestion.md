# 保存、分流与核验

## 先核对授权

- 未指定保存：只在聊天中交付，目标环境保持只读。
- 用户指定保存：确认材料范围、目标目录、允许写入的产物和状态；完整整理稿与候选清单分开保存，原始来源保持原位。
- 用户明确采纳并要求分流：只处理点名的候选和目标位置，不把“认可这个 Skill”当成认可全部候选。

## 查重与命名

先核对材料主体、参与依据、来源 ID、原件路径或链接和问题边界。来源归属未知时可以整理，但标“归属待核”，不按账号、目录或第一人称自动计入某人的经历、复盘或案例。

文件名变化、平台导出、人工修字稿和转写稿可能来自同一事件。结合记录时间、参与者、覆盖范围和内容边界判断；依据不足时保留各自来源身份，不自动合并、覆盖或删除。来源 ID 缺失标“待补”，不现编。

修正归属时只处理有证据表明归属错误的具体材料。单项归属待核不能扩展成整批材料都归属待核；其他已有参与或身份依据的材料保留原确认状态。

同一来源重跑时先比较已有产物和新增范围。内容未变就复用已有产物；确需修订时保留必要版本说明，不未经授权覆盖重要正文。重要覆盖、批量移名和链接更新遵循用户指定的目标规则。

## 写入与读回

1. 读取目标环境的实际规则、字段和索引要求。
2. 只保存用户明确授权的产物，补来源、状态和公开范围；新提炼内容保持待确认。
3. 原件不被整理稿替代。跨位置引用同一正文使用链接，不复制多份权威原件。
4. 写入后从磁盘重新读取文件，核对正文、来源、状态和链接。

逐条检查来源链接、附件路径、时间段或行号是否真实可回查；核对原件未被修改、没有重复正文、隐私没有被自动改成公开。发现单项失败就暂停该项，修好后重新读回核验，并报告未解决问题。
