# 杜一 AI 剪辑 卡片视觉语法

## 第一原则：卡片服务口述

卡片不是把口述改写成更“标准”的逻辑图，而是把说话者已经表达出来的关系变得更容易看懂。判断顺序固定为：

1. 忠于真实口述；
2. 保留口述中的节点、顺序、人物和强调；
3. 让观众更容易理解；
4. 最后才考虑形式逻辑是否整齐。

如果说话者说“录完素材，然后给我的 Agent，然后它帮我剪辑，然后发布”，就画：

`录完素材 → Agent → 剪辑 → 发布`

不得为了让节点词性一致而改成“拍摄 → 自动剪辑 → 发布”，也不得合并说话者单独强调的 Agent。只有原话明确表达因果时才标为 `spoken-cause`；“然后、交给、再、最后”构成的推进使用 `narrative-path`。箭头可以表示时间推进、交接、执行或结果演进，不强制解释为形式因果。

箭头不是预先固定在卡片中的装饰。第一个节点不带箭头；从第二个节点开始，每个节点用自己的 `incoming_connector` 声明与前一节点的连接。渲染器把该连接线绑定到目标节点的 `trigger_word_ids`：目标节点尚未成立时，箭头不可见；到达触发词后，箭头从左向右生长 `0.22s`，目标节点同时渐显。箭头数量永远等于当前关系中已建立的相邻连接数量，不使用 state 级全局 `connector`。

## 固定宽度

- 参考画布 `1280×720`。
- 小卡宽 `373 px`，约占画面 `29.14%`。
- 中卡宽 `427 px`，约占画面 `33.36%`。
- `427 px / 33.4%` 是任何普通卡片的最大宽度，不存在 45% 大卡。
- 左上舞台固定；不得为人物自动换边、缩小或移动。

小卡只服务短单点。中卡服务完整观点和所有关系布局。卡片高度随真实内容自然收口；文字放不下时先缩短动画概念、组织同组复合卡或按语义拆章，不得突破最大宽度。

## 关系布局选择

| `relation_layout` | 何时使用 | 尺寸与排列 |
|---|---|---|
| `single-point` | 一个短结论或提示 | 小卡优先，必要时中卡 |
| `narrative-path` | 原话按“先/然后/交给/最后”推进 | 中卡，2–4 节点单行，节点自然宽，箭头弹性分配余量 |
| `spoken-cause` | 原话明确说“因为/所以/导致” | 中卡，2–4 节点单行 |
| `parallel` | 同一层级的 2–4 个并列项 | 中卡，等宽列铺满 |
| `comparison` | 明确的两面对照 | 中卡，两列等宽 |
| `hierarchy` | 一个上位概念带 1–3 个下位项 | 中卡，上 1、下方等宽 |
| `formula` | 公式、加减、等号或关系符 | 中卡，内容自然宽，关系符弹性填充 |
| `multi-item` | 5–12 个属于同一语义组的短节点 | 中卡，等尺寸均衡换行 |
| `vertical-list` | 按口述逐项增加的 1–4 条清单 | 小卡或中卡，竖向追加 |
| `quote` | 引语与来源 | 小卡或中卡 |
| `chat` | 对话气泡 | 小卡或中卡 |

## 单行分配

- 3 个普通并列节点：每个占内容区 `1/3`。
- 4 个普通并列节点：每个占内容区 `1/4`。
- 流程/推进关系的节点不强行等宽：节点按文字自然宽度，剩余宽度平均分给 2–3 个箭头通道。
- 第一节点与左内边距、最后节点与右内边距保持视觉对称；禁止卡片右侧留下明显空洞。
- 4 个节点加 3 个箭头必须刚好使用中卡内容区，不得为了铺满而扩卡。

## 5–12 节点换行

所有节点保持相同宽度和高度，第二行居中：

- 5 项：`3 + 2`
- 6 项：`3 + 3`
- 7 项：`4 + 3`
- 8 项：`4 + 4`
- 9 项：`4 + 4 + 1`
- 10 项：`4 + 4 + 2`
- 11 项：`4 + 4 + 3`
- 12 项：`4 + 4 + 4`
- 13 项及以上：按真实语义边界拆章。

9–12 项只有在同一编号序列或同一并列组中才允许使用三行复合卡；item 文字、顺序和触发时间不变。不得出现“第一张大、第二张小”或底行节点被拉宽的情况。

## 计划字段

每个视觉 state 必须显式写：

- `fidelity_mode: "spoken-first"`
- `relation_layout`
- `layout_reason`：引用口述中的关系线索，说明为什么选这种排列
- `card_size`
- `content_structure`
- `size_reason`

`relation` 类型允许 2–8 个 `items`。每个 item 必须保留原口述节点的顺序，并分别绑定 `trigger_word_ids`。机器门禁验证尺寸、节点数量、行分配和字段完整性；无上下文 AI 镜头负责判断卡片是否忠于口述、是否误加因果、是否漏掉说话者强调的主体或动作。

`title` 必须是出现当下已经成立的中性主题；不能因为整条计划最终会到“发布”，就在第一节点出现时提前显示“从素材到发布”。`narrative-path/spoken-cause` 的第一个 item 禁止填写 `incoming_connector`，其余 item 必须逐项填写 `incoming_connector: "→"` 或 `"⇒"`；state 级 `connector` 字段禁止使用。其他关系布局不画箭头。5–12 项的行分配由渲染器根据数量确定，计划不得另写列数覆盖。

## 禁止项

- 为了“逻辑更标准”替换、合并、重排或补写口述节点。
- 把“然后”自动升级为因果。
- 只按字符数选择布局。
- 5 项以上仍硬塞单行。
- 把不属于同一语义组的信息强行塞进三行复合卡。
- 卡片超过画面宽度 `33.4%`。
- 右侧留下可容纳一个节点的无意义空白。
