# 卡片内容高度与舞台自动重排合同

## 目标

规则适用于符合输入合同的任意素材。布局必须由当前输入的真实内容和字体测量决定，不得写入某条素材的固定时间点。

## 两阶段判断

1. 计划阶段使用与模板一致的字号、内边距、行高和节点行数估算每张卡片的自然高度。
2. 构建后由浏览器加载 Skill 内嵌字体，HyperFrames 使用实际 DOM 边界复测。

估算只负责提前发现明显问题，浏览器实测是最终权威。不得只按字符数猜高度，也不得用 `overflow:hidden` 把失败隐藏起来。

## 卡片高度

- 卡片宽度仍只有小卡 `373px` 和中卡 `427px`；中卡仍是画面宽度 `33.4%` 的上限。
- 卡片高度不设与内容无关的大号固定底板。
- 短标题或一句短观点按实际内容、字体行高和上下内边距自然收口。
- 正文增加一行，卡片只增加这一行需要的高度；列表增加一项，只增加该项和间距需要的高度。
- `comparison/formula` 等参考组件可以保留保证版式成立的最小高度，但不得借最小高度制造大面积空白。

## 同组复合卡

卡片服务原始表达。只有属于同一语义组、同一编号序列或同一并列关系的信息，才允许合并到一个复合卡外壳：

- `2–4` 项仍使用单行并列或关系布局。
- `5–8` 项使用 `3+2 / 3+3 / 4+3 / 4+4`。
- `9–12` 个短同级项允许使用一个 `multi-item` 复合卡，按 `4+4+1 / 4+4+2 / 4+4+3 / 4+4+4` 换行，末行居中。
- `13` 项以上，或单项文字无法在四列中清楚阅读时，按真实语义边界拆到下一章。
- 合并只改变卡片外壳和空间组织；每个 item 的文字、顺序、ID、触发词和逐层出现节奏保持不变。
- 不同语义组不得为了省空间强行合并；不得为了排版改写说话者关系。

## 舞台预算

固定左上舞台参考高度为 `690px`。在渲染任何动画前，必须先计算章节在所有信息完全出现时的最终高度，而不是只检查第一帧。

预计超过预算时，AI 无需用户审批，按以下顺序自动重排并重新审计：

1. 让短卡回到内容自然高度。
2. 层间距从 `24px` 收紧，但不得低于 `16px`。
3. 把同一语义组的连续信息合并成一个复合卡外壳。
4. 把已经讲完但仍相关的层收拢成摘要条，原信息仍可见。
5. 仍然放不下时，按真实语义边界拆章。

不得自动改变卡片宽度上限、字体、字号、人物位置、语义关系、文字母版或动画触发时间。

## 浏览器实测与重试

HyperFrames 返回 `container_overflow` 时：

1. 流水线把实际矩形、容器矩形、溢出方向和像素量写入布局检查报告。
2. 当前渲染不得继续，也不得把问题交给用户审批。
3. 执行 Skill 的 AI 读取报告，按上述顺序修改 `animation-plan.json`；涉及 item 外壳合并时同步更新 `semantic-reveal-timeline.json` 的 state 事件，但保留 item 事件。
4. 最多完成三轮“重排—审计—实测”。只有三轮都无法解决，才报告技术阻塞。

`data-layout-allow-occlusion`、`data-layout-allow-overflow` 和类似属性不得用于豁免普通卡片或真实截断。

## 交付门禁

- 所有普通卡片宽度不超过画面 `33.4%`。
- 所有卡片高度与实际内容匹配，无明显空壳。
- `estimated_layer_height ≤ 690px`。
- 每个动画项目都有与当前 HTML 哈希绑定的 `layout-check.json`。
- HyperFrames 布局结果中 `container_overflow=0`。
- 最终无上下文 AI 镜头确认：短卡不显空、长组不截断、逐层出现顺序和原始表达未被重排。
