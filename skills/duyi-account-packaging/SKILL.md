# 杜一账号包装

把个人材料转成昵称和可复制的简介。先读取已有资料，缺关键事实再逐项补问；按本次任务范围交付，不要求用户先写成文案。

## 一、输入要求

输入可以是自然语言、口述或资料路径，不要求填写完整表格。

| 输入项 | 要什么 | 缺少时怎样处理 |
|---|---|---|
| 任务范围 | 昵称、简介或两者；给谁做 | 从请求判断，无法判断才补问 |
| 个人材料 | 当前身份或行动、面向谁及其问题、提供的价值，以及本人状态、表达或取舍 | 先读取指定资料并按五项检查覆盖；仍有关键缺口时一次只补一项 |
| 真实凭据 | 相关经历、能力、作品、成果或当前行动及来源 | 可信线索必须收集，数字成绩可选；没有大成绩就用真实行动，不编数字 |
| 已有选择 | 已定昵称、已采纳句、需要保留的表达 | 有就沿用；不将局部采纳扩大为全部确认 |
| 平台与容量 | 平台、具体字段、编辑器实际上下限和格式 | 默认抖音／小红书100–160、B站不超过80；本轮另有范围或容量按用户要求，其他未知字段不编限制 |
| 偏好与参考 | 用户想要的感觉、喜欢的简介写法或本次提供的参考 | 可选；只借鉴写法，不借用他人的身份、经历或成绩 |

启动示例：“给我做账号昵称和简介。个人资料在 {资料路径}，准备发到 {平台}，已有昵称是 {可选}。”

身份与方向都未知时，第一轮只提出一个起点问题，如“你现在主要做什么，或者准备分享什么？”不编身份，不列“昵称待定、简介待定”凑成交付。

## 二、处理边界：要什么，不要什么

| 要做 | 不要做 |
|---|---|
| 基于已有事实和定位表达昵称、简介 | 自动重做完整定位访谈、扩写运营方案、设计头像或封面 |
| 只改用户要求的字段 | 用户只改简介时另起昵称，或改整份定位和身份配置 |
| 区分当前身份、过去成果、当前服务和内容方向 | 将过去做过的事自动写成当前服务、持续内容或未来承诺 |
| 核对事实、数字和行动主体 | 把营收写成利润或个人收入，把学员获得能力写成作者替其完成，借用对标成绩 |
| 以真实问题描述读者，保留用户声音 | 为照顾所有人扩大服务范围，把某种行业、生活方式或价值观套给所有人 |
| 按需要进行参考分析和独立模拟试读 | 每次强制联网、打分或附长分析；将模拟反应当真人反馈、转化率或有效性证明 |
| 标明候选和核验状态 | 未查询就宣称昵称可用、账号包装能涨粉或保证收入 |
| 用户要求保存时更新当前权威原件并读回 | 自动改平台资料、发布，或重组目录、覆盖手工内容和历史 |

当前本人自述优先于过时身份；他人经历、推测和建议不算本人事实。资料互相冲突时指出具体冲突，不用强断言掩盖缺口。

## 简介的五项质量标准

每次生成或修改简介，都按下面五项判断；先检查材料是否足够，交付前再逐项审稿。真实性、承诺边界与字段容量是基础门槛，不代替质量判断。身份、数字成绩、明确人群和行动号召都是可选工具，不是必填格式；不为凑齐元素损失用户的个人表达。

| 标准 | 审核问题 | 要收集的材料 | 不足时怎样修正 |
|---|---|---|---|
| 个人辨识度 | 能感受到这是一个什么样的人吗？有没有属于本人的状态、视角或说话方式？ | 当前生活或职业状态、经历转折、本人常用表达、明确观点或取舍 | 从本人原话和经历中找具体线索；只缺这一项时定向补问，不凭空造人设 |
| 关注理由 | 能知道以后持续看到什么，以及为什么值得继续了解吗？ | 正在做的事、持续内容主题、具体栏目、可分享的方法或过程 | 把宽泛的“分享干货”落到具体问题、动作或内容；不把过去成果当未来承诺 |
| 可信程度 | 有什么真实、具体的线索让人愿意听此人讲？ | 相关经历、作品、结果、年限、当前行动或可公开过程及来源 | 没有大成绩也可用真实行动建立可信度；核对归属与口径，无法确认的事实不进入正文 |
| 记忆点与整体性 | 读完能记住一个核心印象吗？昵称、经历、主张与现在做的事能连起来吗？ | 已采纳昵称、核心主题、价值观、贯穿过去与现在的线索 | 找一条真实主线组织信息，减少无关标签；保留已采纳的表达骨架，不强加口号 |
| 阅读与代入感 | 读起来顺吗？合适的读者能找到与自己的关系吗？ | 读者的具体问题或原话、作者的日常说法、平台呈现方式 | 减少重复、长句和术语；用具体处境表达关系，避免让读者先证明自己有资格 |

五项全部是成稿的必检标准，不能任选几项。每项必须有真实材料与实际文案依据；仅写满字符不算通过。

同一条材料可以支撑多项；记忆点可以由昵称与简介共同承担。个人辨识度可以来自朴素的真实状态，不要求每个人都有宏大价值观。关注理由可以是方法、观点或持续实践，不必都写成服务广告。对标只用于观察表达方式，对标的经历和成绩不能成为用户的材料。

### 成稿的双重门槛与平台版本

- 默认输出两种字数版本：**抖音／小红书共用长版，100–160 字符；B站短版，不超过 80 字符**。共享长版标明适用两个平台，不重复输出两份相同正文。这是本 Skill 的默认交付配置，不作为实时官方限制的验证结论。
- 用户明确只要某个平台、指定其他平台或给出本轮实际容量时，按该范围和容量交付；昵称容量单独处理。简介上限为 160 时下限为 100，区间两端都包含；B站暂未指定下限，不擅自按比例推算。下限与上限冲突时指出具体冲突，不自行放宽。
- 每版最终文案必须同时满足字符范围与五项质量标准。五项都要有具体支撑，不要求写成五个标签或五句话；昵称可以共同承担个人辨识度或记忆点，不能靠字数达标替代质量通过。
- 低于下限时，先补充相关的真实经历、本人表达、持续内容或实践过程，再组织文字；不靠空话、重复、无关履历或未经确认的承诺填字数。高于上限时压缩冗余并重新审核五项。
- 正常交付只给两版都已通过的成稿。任一版不达标就先补材料或改稿；用户跳过关键缺口时报告具体缺口，不能把未达标稿称为完成版。只有用户明确要求先看未达标草稿时，才可例外交付标明问题的草稿，不算完成。

### 简介示例与写法参考

生成简介前读取 [简介示例与写法参考](references/bio-examples.md)。先盘点当前用户已确认的简介及表达选择，再选择适合的写法；已提供的材料不重复询问。

示例使用杜一本人的账号包装，保留已采纳表达与候选的状态，只演示组织方法和审核流程。实际任务仍以当前使用者提供的事实为准，不借用示例或他人的身份、经历、成绩与特有表达。

引用原文、分析和新候选分别标明，保留当前稿、历史稿、已采纳与待采纳的状态。改写后的候选不能标为原文。

### 生成前的材料收集

1. 先盘点本轮口述、已采纳表达和用户指定资料。存在资料库时按该库的读取规则定位本人背景、日记、经历记录、作品、产品与内容原件，只在本次允许范围内检索，不要求用户另建库或重新填写全部信息。
2. 按五项建立内部材料表：`标准｜原话或具体材料｜来源位置｜事实/偏好/推断状态｜公开边界｜剩余缺口`。库里的第一人称、他人案例和旧的 AI 分析不能直接当本人事实；当前状态优先于过时资料，有冲突先核对。
3. 现有资料能覆盖的内容不再问。确有缺口时，每轮只补最影响这版简介的一项，例如“你为什么愿意长期讲这件事？”“你做过或正在做的哪一件事可以公开？”“读者关注后会持续看到什么具体过程？”。先找库，再补问；没有可访问库就直接补问。
4. 不要求每项都提供独立故事、精确数字或正式证明。一项真实经历、当前行动或本人表达可以支撑多个标准。收集到足以形成个人线索、持续内容预期、可信依据和一致主线的材料后就起稿，不为凑履历反复追问。
5. 用户明确跳过时尊重跳过，报告对应质量或字符缺口；不能把“跳过”转成虚构身份、成绩或价值观。只有用户明确要求先看未达标草稿时，才按例外交付并标明未通过项，不报告完成。缺口导致无法起稿时只提出一个关键补问。

### 输出前的五项审核

- 对每版实际要交付的简介逐项记录：`标准｜通过/需修改/缺材料｜文案依据｜修正动作或缺口`。不能只写“已审核”就结束。多方案或多平台必须逐版审查；可用五行、多方案列的紧凑表，但每格依据必须对应那一版，不能拿另一版的经历或句子替它通过。
- “需修改”先改稿，再检查受影响的五项、事实和字数；压缩或合并后的最终原文也要复审，不能沿用长版结论。
- 材料缺口先回到检索或定向补问。用户跳过且仍有缺口时报告未完成项；只有明确要求先看未达标草稿时才例外交付，审核状态保持“缺材料”，不能称为五项通过或完成版。
- 没有未解决问题才报告“五项审核通过”。默认在可复制正文外给五项简表：`标准｜状态｜对应文案或缺口`；每项至少一条具体依据，不能仅用“已审核”或“五项通过”替代。用户明确只要文案时不展示表，但仍须完成内部逐项审核。审核记录、来源和问题说明不进入简介正文。
- 五项自审每次执行；独立读者模拟只在用户要求或确有误读问题时执行，二者不互相替代。文本审核不证明实际关注率或转化效果。

## 三、生成规则

1. 先按五项收集并核对材料，判断哪些信息已有，哪些确实缺。完整定位尚未明确且包装无法继续时指出具体缺口；需要完整定位访谈时，由用户决定另行进行，不自动扩大本次任务范围。
2. 只提供本名或要求保留本名，仍按未定昵称处理；明确指定已定账号名才沿用。昵称未确定时，默认给 3 个有真实区别的候选及 1 个推荐；用户指定数量时按其要求。可以比较个人名、名字加领域、实践主题或已明确价值观，不默认谐音、人设口号或英文名。已定昵称只沿用。连续被评价刻意或尴尬时辨别问题，必要时问一个具体偏好，不无限换同类词。
3. 简介按五项标准组织信息；默认输出两种字数版本：抖音／小红书共用长版和B站短版，按字数选相关身份和凭据，不强制固定顺序或塞入全部履历。保留已采纳的个人表达与组织线索，不能为了短而只剩一段通用业务说明。
4. “有经验、有技能”造成资格疑问时，可用做过的事情或具体卡点表达；阶段覆盖由真实定位决定。用户担心依赖时把重心转到读者获得的方法及自主行动，仍须符合实际角色。“帮”不是禁词，“分享”不是所有人的默认动词。
5. 起稿前先读本人现行材料及“简介示例与写法参考”。需要分析用户提供或要求查找的账号时，只借鉴表达方式，不借用其身份、经历、成绩或个人原句。参考写法的存在不证明有效。陌生品牌可准确换成通用类别，不凭陌生就编造平台引流风险。
6. 用户要求审稿，或存在需要检验的代入、阶段覆盖、误读问题时，读 [reader-review.md](references/reader-review.md)。有委派能力时独立试读，否则标明主线程模拟；代理只读，主代理验收。简单改名或压缩不强制独立试读，简介五项自审仍须执行。正文与分析分开。

## 四、字数与事实限制

- 上限绑定具体字段。用户给的简介上限不能套给昵称。优先采用实际编辑器限制；需要核验未知限制时查当前官方说明或实际字段，不把历史平台数字或可填示例长度当固定官方上限。
- 最终原文中的标点、空格、字母和换行全部计入；昵称与简介分开计数。计数输入必须与最终可复制文案逐字一致，不额外添加文件末尾换行；文案本身需要的换行原样保留。短字段或用户要求单段时不换行。
- 必须实际运行 `scripts/count_chars.py`，不能估算后标成实测。优先用 `--text` 直接统计最终文案；使用 `--file` 时，文件内容必须与该文案逐字相同。默认长版使用 `--min 100 --limit 160`，B站使用 `--limit 80`；有本轮给定条件时用对应上下限。在 Skill 目录运行，或使用脚本绝对路径：`python3 scripts/count_chars.py --file {文案文件} --min {该字段下限} --limit {该字段上限}`；没有下限或上限时省略对应参数。也支持 `--text` 和 `--stdin`；无上限时不传 `--limit`。
- 默认按 Unicode 码点计数，同时报告 UTF-16 单元数。有差异或平台口径不明时明确这是本地计数；平台实测以编辑器接受结果为准。用户已反馈填不下时，按实际约束调整，不坚持本地结果。
- 必须同时达到下限且不超过上限；160上限的简介不能少于100字符。低于下限先补真实材料并改稿，高于上限先减冗余。有余量不必凑满；不能靠重复或空话达标。
- 压缩后逐项核对独立问题、动作、主体和成果口径。“怎么卖”不能只剩“变现”，“能独立完成”不能变成“替其完成”，明确做过的事不能只剩含糊“实践”。核心内容确需删减时在正文外说明。
- 不知道昵称上限或可用性时只报告已核验的部分，不编造。缺事实标在文案之外，不把“待补”或内部说明混入可复制简介。

## 五、输出格式

按下列模板输出，替换花括号，不留下模板占位。只保留用户要求的字段，不另写策略报告。推荐理由和重要取舍各最多一句；用户另有要求时按其要求展开。生成简介时在文案与字符表之后补五项审核简表，未通过的项明确指出。只改昵称时不生成简介，也不强制补简介材料。

### 材料不足，无法起稿

只输出一项关键补问：

```text
请先告诉我：{最重要的一项问题}？
```

### 昵称与简介都需要，昵称尚未确定

```text
昵称候选：
1. {昵称1}
2. {昵称2}
3. {昵称3}
推荐：{一个昵称}。{一句理由}

抖音／小红书简介（共享长版）：
{100–160字符、五项全部通过的纯简介}

B站简介（短版）：
{不超过80字符、五项全部通过的纯简介}

字符核对：
```

接一张表，不将统计写入简介正文：

| 字段 | 本地字符数 | 下限 | 上限 | 区间结果 |
|---|---:|---:|---:|---|
| 昵称1 | 实测数值 | 未提供 | 未提供 | 仅计数 |
| 昵称2 | 实测数值 | 未提供 | 未提供 | 仅计数 |
| 昵称3 | 实测数值 | 未提供 | 未提供 | 仅计数 |
| 抖音／小红书共享长版 | 实测数值 | 100 | 160 | 必须通过 |
| B站短版 | 实测数值 | 未指定 | 80 | 必须通过 |

简介后另附五项简表，每项给“通过/需修改/缺材料”和一条对应文案或缺口；需修改必须先修正，不能把未改稿称最终定稿。两种字数版本分别给计数与五项依据；其他平台仅在本轮要求时追加。用户明确只要一个平台或给定单一容量时，模板只保留该版本并采用其条件。已确定昵称时，将候选与推荐区换成“昵称：{已定昵称}”，只列该昵称的计数行。未知上限填“未提供”，余量填“不适用”。

### 只改一个字段

仅输出该字段、计数和必要的一句说明。只改简介也默认交付上述两种版本；明确只要单平台或给定单一容量时采用下面格式：

```text
{平台或“通用”}简介：
{可直接复制的纯简介}
字符：{实测数值}，要求{已知下限至上限，或仅上限}；区间检查{通过/未通过}。
取舍：{仅在有重要删减时写一句}
简介审核：
```
