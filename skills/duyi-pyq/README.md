# 杜一朋友圈（duyi-pyq）

**借鉴 ISO 通俗语言原则与航空航天技术文档的清晰表达方法，保留你的口吻，把一件事讲清楚。**

发来一段口述、刚完成的事项或已有草稿，AI 会选择合适的内容结构，整理成可直接复制的朋友圈，并告诉你具体改了什么。材料不足时先请你补充，不编经历，也不为了简洁把内容压成摘要。

## 采用哪些方法

| 方法与完整名称 | 在这里解决什么 |
| --- | --- |
| **ISO 24495-1:2023 — Plain language — Part 1: Governing principles and guidelines**（通俗语言：第 1 部分，指导原则与指南） | 内容与读者相关，重点容易找到，表达容易理解，信息能够使用 |
| **ASD-STE100 — Simplified Technical English**（简化技术英语，参考 Issue 9） | 借鉴航空航天维护技术文档中的清晰表达思路：明确动作、一段一个主题、减少歧义、保持术语一致 |
| **中文文案排版指北 — Chinese Copywriting Guidelines** | 统一中英文空格、数字与单位、中文标点及专名写法 |

这里采用的是适合中文朋友圈的原则与方法提炼。ASD-STE100 本身面向英文技术文档，不机械套用它的英文词典和词数限制。本项目没有经过 ISO 或 ASD 认证，也不宣称「航天级写作」或符合全部标准。

实际执行方法已经放入本地 [清晰表达附件](references/plain-language.md) 与 [中文排版附件](references/chinese-typesetting.md)，不用每次联网查标准。需要事实查证或调研时仍可联网。[来源记录](references/sources.md)供追溯。

## 怎么使用

### 在支持 Skill 的 AI 工具里

下载 [duyiskills](https://github.com/duyi2076/duyiskills)，或在终端获取：

```bash
git clone https://github.com/duyi2076/duyiskills.git
cd duyiskills
mkdir -p ~/.agents/skills
cp -Rn skills/duyi-pyq ~/.agents/skills/
```

以上适用于首次安装，复制命令保留已有文件。更新时先备份自己的修改，再对照新版本替换，避免把两个版本混在一起。

随后为实际使用的工具配置入口。例如 Codex：

```bash
mkdir -p ~/.codex/skills
ln -s ../../.agents/skills/duyi-pyq ~/.codex/skills/duyi-pyq
```

Claude Code 的入口是 `~/.claude/skills/`，Hermes 的入口是 `~/.hermes/skills/`，软链接同样指向 `~/.agents/skills/duyi-pyq`。已有同名入口时先检查目标，安装后在新会话中确认工具能读取 Skill。

也可直接把完整文件夹放入所用工具的 Skill 目录。运行只需要能读取 Markdown 附件的 AI 工具，无需 API 密钥、浏览器登录或额外运行软件。

然后直接说：

```text
用 duyi-pyq，把下面这段整理成朋友圈：

【粘贴你的材料】
```

### 在普通 AI 聊天里

打开 [prompt.md](prompt.md)，复制其中的完整提示词，再接上你的材料。无需本机目录或 Skill 加载能力。

## 你需要输入什么

不用先选模板或填写固定表格。以下任一种材料都可以：

- 刚完成的一件事：做了什么、怎么做、目前观察到了什么。
- 一段口述：可以重复、跳跃、没理顺，保留你自己的想法就好。
- 已有草稿：注明想保留的句子，以及是否有长度或语气要求。
- 方法或招募介绍：提供真正可执行的步骤，或已经确定的交付、价格、周期与边界。

有日期就保留日期；有结果就给结果，还没结果就说正在尝试。没有客户也可写自己的测试。涉及别人时说明哪些内容可以公开。

可选要求，例如：

```text
保留我的细节和思考过程，不限字数。
```

```text
控制在 200 字以内，只给正文。
```

若材料不足以支持成稿，AI 会集中指出缺什么，等你补充后再写。例如你提到一个练习却没交代练法，它会问具体步骤，不自行编造。

## 它怎么整理

1. **检查材料**：分清发生的事、实际动作、观察、判断和计划，必要时先补料。
2. **检查读者印象**：看措辞是否居高临下、贴标签或夸大自己；角色不明确时不硬解释。
3. **选择内容结构**：知识技巧、案例反馈、观点洞见、产品介绍及招募。结构服务材料，不要求填满模板。
4. **完整改写**：保留主线、关键细节、思考过程与口吻，只删重复和无关内容。
5. **复核并交付**：检查事实、作者角色、信息完整性与排版，再说明实际改动。

真实观点和不同意见可以保留。目标是让表达有判断、有帮助，也尊重读者，不把同行分享改成专家训话。

## 它会输出什么

默认是一个版本，按以下顺序输出：

1. **朋友圈正文**：纯文本，自然分段，段间空一行，可直接复制。
2. **修改说明**：具体指出顺序、重复、旁支、措辞或排版的调整。
3. **待核对**：有疑点才出现，不混进正文。

正文不自动加标题、加粗、标签、表格或引用块。必要引用用「」，嵌套用『』，普通提问和强调不滥用引号。默认不限字数，仅在你要求时精简。日期与时间不自动纠正；有疑点在正文外提醒。

## 输入与输出示例

以下为演示材料，不代表作者真实经历或经过验证的效果。

**输入：**

```text
帮我整理成朋友圈：
昨天我把一节课在白板上讲完并录音，再把转写交给 Kimi 整理 PPT。
检查发现一页漏了适用条件，我补回去了。
以前直接从空白 PPT 开始，容易卡在先放哪一页。
这次先讲再整理，我更清楚内容顺序了，还没统计省了多少时间。
```

**输出示例：**

```text
昨天我在白板上把一节课讲完并录了音，再把转写交给 Kimi 整理 PPT。

检查时，我发现有一页漏掉了适用条件，就把它补回去了。

以前直接从空白 PPT 开始，很容易卡在先放哪一页。这次先讲再整理，我更清楚内容顺序了。

还没统计这次省了多少时间，先记下这个过程。

修改说明：
保留了讲课、录音、转写、检查补漏和未统计时间的信息，按操作顺序分段，统一了 AI 工具名与 PPT 的空格排版。
```
