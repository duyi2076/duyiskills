# 四类内容的可选结构

## 知识技巧

- 小方法：具体场景与问题 → 实際可执行的步骤 → 易漏细节或适用条件。
- 真实问答：实际提问 → 有条件的回答 → 一个最小动作。
- 检查清单：任务 → 每项检查及通过标准 → 如何处理关键未通过项。

避免只报工具名而不说问题，避免把未经测试的建议写成已验证方法。

## 案例反馈

- 服务变化：真实起点 → 做了什么 → 已观察变化 → 尚未确认的结果。
- 用户反馈：可公开原话 → 对应交付 → 有限结论。
- 自测过程：目标 → 实际动作 → 观察 → 下一次调整。

没有客户也可写自测，不冒充客户案例。收到“有用”的反馈不等于成交或收入增加。公开他人案例需确认可公开范围，不因打码就推定许可；必要公开范围不清楚时先要求补充，不绕过缺口凑稿。

## 观点洞见

- 新认识：真实事件 → 原来的理解（仅材料有时写） → 新判断 → 行动改变。
- 取舍：备选项 → 现实约束 → 选择理由 → 代价或重新考虑的条件。
- 踩坑：旧做法 → 具体问题 → 调整 → 可供参考的最小改变。

复盘可以只讲一个发现，不必变成自我批判；不从情绪推断人格或心理诊断。不为了凑结构发明用户过去的想法。

## 产品介绍及招募

- 产品介绍：谁在什么场景遇到什么问题 → 实际交付 → 形式、周期、价格 → 适合与不适合 → 一个真实入口。
- 首批体验：已经准备好的部分 → 想验证的具体问题 → 双方要求 → 时间与费用 → 仍在打磨的部分 → 入口。
- 购买疑问：真实疑问 → 明确回答 → 交付与边界 → 下一步。

不能虚构稀缺、倒计时、销量和“很多人都问”。缺价格等信息时不擅自定价；招募所需关键条件不足时先集中要求补充，收到后再成稿。

## 选型

用户分享复盘并产生新认识，优先观点洞见；用户主要教人怎么操作，优先知识技巧。同一材料存在两种用途时，按用户表达重点选一种，不必展示选型过程。
