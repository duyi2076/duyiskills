# 杜一朋友圈

## 交付与边界

默认交付一个可复制的朋友圈正文及具体修改说明。材料足够就直接改写，无需用户确认提纲或选择模板；材料不足先问清，不勉强成稿。

保留用户当前指令、原创判断、关键表达与关系姿态。默认完整叙述、不限字数，只删重复和无关内容；明确要求精简或指定字数时才压缩。短句不等于短摘要，不为写长补造内容。

只在聊天交付。保存、检索私有资料和发布须有对应任务授权；此 Skill 不自动执行这些动作。方法已内置于本地附件，写作规则优先直接读取本地提炼，不需要每次联网查标准；任务需要调研、事实查证或更新方法时可以联网，不能用外部资料编造用户经历。材料不足仍要求用户补充必要的本人材料。来源记录在 [sources.md](references/sources.md)，普通改写不读取该文件。

## 执行流程

### 1. 判断材料是否足够

识别真实事件、实际动作、观察结果、作者判断以及计划或建议。按 [类型结构](references/templates.md) 选择最贴材料的结构，模板不必填满，不需要展示选型过程。

如果缺项影响内容成立、操作可用、产品承诺或案例公开，集中要求补充具体材料，收到后再写。不问已有信息或无关资料；没有数字、客户或最终结果不等于材料不足。不能通过删掉关键内容、泛化或编造绕过缺口。

事实与数字有疑点时按 [材料与事实边界](references/material-fidelity.md) 处理。

### 2. 改写前检查角色

读取 [读者视角与作者角色](references/reader-role.md)，内部检查原文可能造成的印象。保留真实观点，避免居高临下、羞辱贴标签、夸大权威或贬低别人抬高自己。角色不明确时不强行归类。

### 3. 完整改写

围绕一条主线保留具体场景、思考过程、关键细节、转折及行动变化。相关事件可串联，不拼造事件。普通工作不必拔高成大道理，无感悟可写过程，无客户可写自测，无结果可写进展。

读取 [清晰表达方法](references/plain-language.md) 与 [中文排版规则](references/chinese-typesetting.md)。它们分别帮助读懂与规范排版，不改变事实、口吻或信息完整性。

正文用朋友圈式纯文本，自然段之间空一行，段落长短随语义；不每句另起一段、不按屏幕宽度硬换行。不自动加标题、标签、emoji、钩子、反问或销售入口。无需 Markdown 加粗、小标题、引用块、表格、分隔线和代码框；确有步骤才用普通编号。用户指定格式优先。

### 4. 改写后复核

对照原材料检查事实主体、因果、日期、观点、关键细节和情绪是否保留，计划和建议是否被误写成已实现效果。复核作者角色是否被改成专家训话或权威指导；发现不必要的变化就恢复。

检查方法是否可操作、正文是否自然完整、排版是否符合附件。模型自检不等于读者测试，不宣称受欢迎或效果已经验证。

### 5. 输出并说明修改

直接从朋友圈正文开始，不加「正文」标题。正文结束后空行，输出「修改说明：」，简短说清实际改变的顺序、重复、旁支、措辞或排版。不要只说「优化了表达」。涉及观点、角色、事实表述或承诺强度的变化，应指出原表达及处理方式。无实质改动时如实说明。

有疑点再输出「待核对：」，没有则省略。说明和核对项不混入正文。可简述类型与主线，但不能替代修改说明。用户明确说只给正文时省略说明；必要补料或关键矛盾仍需先问。

## 在其他 AI 中使用

用户需要独立提示词时提供 [prompt.md](prompt.md)。该提示词是同一流程的可复制入口，不依赖附件或本机路径；修改本 Skill 时同步维护它。
