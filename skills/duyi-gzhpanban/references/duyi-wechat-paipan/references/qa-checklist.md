# 公众号排版 QA Checklist

排版、预览、生成复制稿或 API 片段，以及进入发布前执行。

## 双模式

- copy 正文交付为纯 HTML，正文无 `id`、`class`、`<style>`、script、按钮和使用说明；图片为编号占位，原图、配图清单、配图复制页和复制使用说明另附。配图复制页只含原图、编号及前后文定位。
- copy 不自动操作剪贴板、不自动进入微信后台或保存草稿；用户明确代为粘贴时才调用已有浏览器粘贴能力。
- api 交付保留唯一 `id="output"` 和原图 `src`；`--mode api` 不能单独触发上传，只有 API 创建草稿时才自动上传图片。
- `--mode api --standalone` 只生成含图浏览器预览，不能作为 API 交付稿；standalone、含图预览和总览产物必须写 `wechat-delivery-mode=preview`，发布后端拒绝 `copy` 和 `preview` 标记。提交前必须使用不带 `--standalone` 的 api 片段。
- API 发布不得直接提交带编号占位的 copy HTML。必须从同一份排版 Markdown 重新生成 api 版，只切换交付格式，不重新选重点或改正文；缺 Markdown 时从原文和配图清单恢复真实图片引用并核验。带 `wechat-delivery-mode=copy` 标记必须被拒绝。
- 含图预览只作核对；复制验收必须检查贴进微信后台后的实际效果。浏览器预览或模拟剪贴板只能作辅助，不能宣称已完成微信粘贴验收。

## 正文完整性

- 正文句子、标点、事实、数字、图片、列表、表格、公式和论证顺序与原文一致。
- 默认不删句末句号。
- 首个文章标题只在标题元信息中出现，没有重复进入正文。
- 原文已有的内容或实际强调全部保留。
- 主动选择的新增重点都能在原文找到，未新增判断、解释或事实。

## 重点选择

- 分析稿记录了文章主线、真实论证阶段和每个重点的原文定位。
- 长文逐个论证阶段评估重点，数量由内容决定，不使用固定配额。
- 行内重点是原文关键短语。
- 块级 `::: emphasis` 是原文完整句或段，使用所选主题的 blockquote 样式。
- 真实引用仍使用 `>`。
- 重点块不只框数字或成绩，不去掉限制条件，不把观点变得更绝对。
- 普通正文与重点块有实际可见差异。

## 固定风格

- 只使用 15 个 style id：`minimal`、`medium`、`wired`、`verge`、`stripe`、`apple`、`ft`、`linear`、`github`、`notion`、`magazine`、`editorial`、`newspaper`、`course`、`event`。
- 无指定时使用 `minimal`；全量任务输出 15 套。
- 每份 HTML 只使用一套主风格。
- 字号、颜色、行高、h2 和 blockquote 样式与 `templates/styles.md` 对应条目一致。
- 深色主题中文字与背景有足够对比，不能同色。

## 手机阅读

- 390px 视口完整通读首屏、中段和结尾。
- 段落密度、标题层级、重点块和图片停顿自然。
- 文本无溢出、重叠、裁切或密成一坨。
- 列表、表格、公式和图片均可读且未丢失。

## WeChat HTML

- API 片段保留唯一 `id="output"`；copy 片段不得保留发布入口属性。
- API 保留真实图片引用；copy 只保留编号定位，可见链接文字保留。
- 所有可见元素有内联 `style` 属性。
- 无其他 class、id、data 属性、`<style>`、script、外部样式资源、伪元素或 JavaScript。
- 正文无字面量 `\\n`、裸 Markdown 控制符或未处理公式命令；代码块中的合法转义字符保留。
- QA gate 通过后才交给发布流程。
