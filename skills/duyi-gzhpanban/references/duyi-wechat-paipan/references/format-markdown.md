# 公众号排版格式规范

用于把已写好的文章整理成手机可读的 Markdown 和双模式 HTML。

## 输出模式

- 默认 `copy`：输出纯 HTML 复制稿，正文无 `id`、`class`、`<style>`、script、按钮和使用说明；图片改为编号占位，另附原图、配图清单、配图复制页和复制使用说明。配图复制页只含原图、编号及前后文定位，用户可右键复制图片后粘到微信后台。
- copy 不自动操作用户剪贴板、不自动进入微信后台或保存草稿；代为粘贴须明确交给已有发布模块的浏览器粘贴能力。实际微信粘贴效果必须单独验收。
- `api`：输出 API 草稿 HTML，保留唯一 `id="output"` 和原图 `src`。模式只决定输出格式，不授予网络提交权限；API 创建草稿时才自动上传图片。
- API 发布不能直接提交 copy 版占位 HTML。已有 copy HTML 要从同一份排版 Markdown 重新生成 `--mode api`，只切换交付格式，不重新选重点或改正文；缺 Markdown 时依据原文和配图清单恢复真实图片引用并核验。带 `wechat-delivery-mode=copy` 标记的文件由发布后端拒绝。
- `--mode copy|api` 与 `--all/--preview/--style` 独立。批量未指定 style 集合时生成全部 15 套。

## 内容保护

- 排版默认保留句子、标点、事实、数字、图片、列表、表格、公式和论证顺序。
- 默认不删句末句号，不为追求节奏改写句子。
- 开篇一级标题只作为标题元信息，不进入正文；其余正文一级标题降为二级。代码内的 `#` 不参与标题识别。
- 图片保留原位置，除非分析稿给出阅读停顿或理解上的理由。

## 固定风格

唯一风格权威是排版模块相邻的 `duyi-wechat-css-layer/templates/styles.md`。只使用：

```text
minimal / medium / wired / verge / stripe / apple / ft / linear / github / notion / magazine / editorial / newspaper / course / event
```

无指定时使用 `minimal`；批量默认生成全部 15 套。每个文件只能有一套主风格。

## 排版分析

完整文章先生成 `{filename}-paipan-analysis.md`，记录主线、自然分节、长段落问题、独立成行候选、重点选择、图片/停顿点、style id 和不改写检查。分析稿不进入最终正文。

## 重点标记

通读原文后主动选重点。重点数量由文章的真实论证阶段决定，不设固定配额。

```markdown
普通正文中的 **关键短语**

::: emphasis
原文完整句或完整段
:::
```

- 行内重点必须是原文中的短语。
- 强调块必须是原文完整句或完整段，重用所选主题的 blockquote 样式。
- `>` 只用于真实引用、原话或引用语境。
- 不新增解释、不复制原句、不改变顺序，不去掉限制条件，不把观点变得更绝对。
- 数字、成绩或价格只有在它承担核心判断时才进入重点，不能单独框数字。
- 选块理由和原文定位只放分析稿。

## Markdown 语义

- `##` 只用于真实章节转折。
- `###` 只用于局部转折或已有的小标题。
- 列表、表格、分割线和公式保留原语义。
- 文件路径、命令、产品名和代码词保留反引号。
- 不新增原文没有的事实、例子和结论。

## HTML 契约

- 微信片段保留唯一 `id="output"`。
- 每个可见元素的样式写在 `style` 属性中。
- API 清理 class、data 属性、`<style>`、script、外部样式资源和伪元素，并保留真实图片引用；copy 图片改为编号定位，可见链接文字保留。
- QA gate 通过后才进入发布流程。
